# 测试计划 · 易淘商城接口

## 1. 测试目标

验证易淘商城后端核心业务链路的正确性与健壮性，重点覆盖：

1. 用户注册 / 登录 / 鉴权的正常与异常路径
2. 商品列表分页与筛选的边界行为
3. 购物车增删改与用户隔离
4. 订单全生命周期（下单 → 支付 / 取消）及**库存数据一致性**
5. 高并发场景下的库存正确性（是否超卖）
6. 水平越权（能否操作他人资源）

## 2. 测试范围

| 范围内 | 范围外 |
|---|---|
| 全部 14 个 HTTP 接口的功能与异常分支 | 前端页面 UI |
| 订单状态机迁移的合法性与非法迁移 | 数据库层实现（当前为内存存储） |
| 库存扣减 / 回滚的一致性 | 支付网关真实对接 |
| 并发下单竞态、重复提交幂等性 | 性能压测、长时间稳定性 |
| 接口级权限校验 | 网络安全、渗透测试 |

## 3. 测试策略

采用**分层测试**，先保证功能正确，再用专项用例攻击薄弱点：

| 层次 | 内容 | 对应用例 |
|---|---|---|
| L1 冒烟 | 服务能起、登录 → 加购 → 下单 → 支付主链路通 | `tools/smoke_check.py` |
| L2 功能 | 各接口正常路径 + 参数校验 + 边界值 | `tests/test_*.py` 共 48 条 |
| L3 专项 | 状态机、幂等性、并发、越权 | `tests/bugs/` 共 5 条 |

### 用例设计方法

- **等价类划分**：手机号（空 / 11 位 / 太短 / 太长 / 含字母）、密码（空 / 5 位 / 6 位）
- **边界值分析**：密码长度 5 与 6、库存恰好相等、分页超出范围、`size=1`
- **状态迁移法**：订单状态 PENDING / PAID / CANCELLED 的全部迁移组合
- **错误推测法**：重复提交、并发提交、用他人 ID 访问
- **场景法**：完整下单链路

## 4. 测试环境

| 项 | 内容 |
|---|---|
| 操作系统 | Windows 11 |
| 运行时 | Python 3.13 |
| 测试框架 | pytest 9.1.1 |
| 被测服务 | 本地 `127.0.0.1`，端口由系统分配（`port=0`，避免端口冲突） |
| 依赖 | 仅 pytest（被测系统本身零第三方依赖） |

## 5. 准入 / 准出标准

**准入**：被测服务能正常启动，冒烟脚本通过。

**准出**：
- L2 功能用例 **100% 通过**；
- 已发现的缺陷全部有对应复现用例，且用例稳定复现（不闪烁）；
- 输出测试报告，缺陷清单含级别与修复建议。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 并发缺陷偶发不可复现 | 测试结论不稳定 | 被测系统显式模拟持久层延迟（`DB_ROUND_TRIP`），把竞态窗口放大到稳定可复现 |
| 内存存储，用例间数据污染 | 结果互相干扰 | `autouse` fixture 在每个用例前重置数据 |
| 端口占用导致服务起不来 | 用例集体失败 | 用 `port=0` 让系统分配空闲端口 |
