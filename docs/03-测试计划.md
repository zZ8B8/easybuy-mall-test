## 1. 测试目的

对易淘商城 V1.0 的主流程（浏览 → 购物车 → 下单 → 支付 / 取消）进行系统测试，
验证功能是否满足《需求规格说明书》，并在过程中发现缺陷、评估质量、给出上线建议。

本项目的特殊之处：产品**刻意内置了 8 个缺陷**。测试的目的除了「验证功能」，
还包括「证明这些缺陷确实能被测试手段发现」，因此**缺陷发现率是核心质量指标之一**。

## 2. 测试范围

### 2.1 纳入范围

| 模块 | 测试内容 |
| --- | --- |
| 用户模块 | 注册、登录、鉴权、资料查询 |

| 优惠券模块 | 领券中心、领券、券包、限领校验、门槛校验、用券抵扣、金额计算、券返还、过期券 |
| 数据层 | 库存流水一致性、金额恒等式、券状态一致性 |
| 页面 | 首页、详情、登录、购物车、订单页的可用性与交互 |

### 2.2 不纳入范围

| 内容 | 原因 |
| --- | --- |
| 真实支付网关对接 | 靶场不接入真实支付 |

## 3. 测试策略

| 测试类型 | 方法 | 工具 |
| --- | --- | --- |
| 功能测试 | 等价类划分、边界值分析、判定表、场景法 | 浏览器、Postman |
| 接口测试 | 直接调接口，绕过前端 | Postman / Apifox / pytest |
| 数据校验 | 反向查库，比对库存与流水 | Navicat、SQL |
| 并发测试 | 多线程同时下单，验证不超卖 | pytest + threading |
| 越权测试 | 用 A 的 token 操作 B 的资源 | Postman |
| 抓包分析 | 观察请求头、参数、响应 | Fiddler |
| 回归测试 | 缺陷修复后重跑用例 | pytest |
| 兼容性 | 主流浏览器各跑一遍 | Chrome / Edge / Firefox |

### 3.1 测试设计方法示例

**边界值分析**（下单数量）：

| 点 | 值 | 预期 |
| --- | --- | --- |
| 下边界 | 1 | 成功 |
| 边界 | 99 | 成功 |
| 边界外 | 100 | 拒绝 INVALID_PARAM |
| 非法 | 0 / -1 | 拒绝 |
| 超库存 | 库存+1 | 拒绝 INSUFFICIENT_STOCK |

**等价类划分**（登录）：

| 类 | 数据 | 预期 |
| --- | --- | --- |
| 有效 | 正确用户名 + 正确密码 | 成功，返回 token |
| 无效·密码错 | 正确用户名 + 错误密码 | 401 |
| 无效·用户不存在 | 不存在用户名 + 任意密码 | 401 |
| 无效·空 | 空用户名 / 空密码 | 400 |

## 6. 准入与准出标准

### 6.1 测试准入（进入执行阶段的前提）

1. 数据库可正常初始化，服务能启动并返回 `/health` 为 UP。
2. 前端 6 个页面（首页 / 详情 / 登录 / 购物车 / 订单 / 领券中心）均可正常打开，静态资源加载无 404。
3. 接口文档（02）与实现一致，无未定义接口。
4. `seed.sql` 数据完整（3 用户 / 6 商品 / 6 券），库存与流水一致。

### 6.2 测试准出（判定可交付）

| 指标 | 标准 |
| --- | --- |
| 用例执行率 | 100% |
| 用例通过率 | ≥ 95%（不含刻意缺陷对应的预期失败） |
| 严重缺陷 | 全部已提交、已复现、有明确复现步骤 |
| 高危缺陷修复验证 | 修复后回归通过 |
| 文档 | 用例、缺陷报告、测试报告齐全 |

> **本靶场的特殊约定**：8 个内置缺陷在 V1.0 中**不会被修复**，
> 它们以 `xfail(strict=True)` 固化在回归套件里。准出结论应为
> **「不通过 / 有条件通过」**，并在报告中明确列出风险。

## 7. 缺陷分级标准

| 等级 | 定义 | 示例 |
| --- | --- | --- |
| 严重（Blocker/Critical） | 数据错乱、资金/库存损失、越权泄露 | BUG-003 超卖、BUG-004 越权、BUG-007 折扣算反 |
| 高（Major） | 主流程逻辑错误、状态机错误 | BUG-001、BUG-002、BUG-006 券重复抵扣 |
| 中（Normal） | 非主流程功能错误、校验缺失 | BUG-005、BUG-008 限领校验 |
| 低（Minor） | 文案、样式、体验问题 | — |

| 优先级 | 定义 |
| --- | --- |
| P0 | 必须立即修复 |
| P1 | 本迭代内修复 |
| P2 | 可延后 |
| P3 | 建议修复 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 并发缺陷偶现，难稳定复现 | 回归不可信 | 用 `SIMULATE_DB_LATENCY` 放大竞态窗口 |
| 数据库连接建立慢（~0.27s） | 并发请求被串行化 | 使用连接池 + 启动预热 |
| 多窗口同时操作数据互相污染 | 结果不可信 | 每条用例前自动重置数据 |
| 手工测试易漏接口层问题 | 覆盖不全 | 功能 + 接口 + 数据三层交叉验证 |
| 缺陷修复后旧用例失效 | 回归假绿 | 用 `xfail(strict=True)`，修复即报 XPASS |
