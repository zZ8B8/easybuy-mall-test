## 1. 项目背景与目标

易淘商城是一个 B2C 电商系统，覆盖「浏览商品 → 加入购物车 → 下单 → 支付 / 取消」
这条完整主流程。系统的**真实目的是作为测试练习靶场**：除了正常功能，它刻意包含了
8 个典型缺陷（状态机、幂等性、并发、越权、参数校验、券状态、金额计算、限领校验），
供测试人员通过黑盒与自动化手段发现。

业务目标：

1. 提供一条可运行的电商主流程，供功能测试、接口测试、性能测试使用。
2. 提供真实数据库（MySQL），供 SQL 校验、数据一致性反向验证使用。
3. 内置可复现的缺陷，供缺陷管理流程（提交、复现、回归）练习。

## 2. 用户角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 游客 | 未登录用户 | 浏览商品列表、查看商品详情、注册、登录 |
| 会员 | 已登录用户 | 游客全部权限 + 购物车管理 + 领券/用券 + 下单 + 支付/取消本人订单 |
| 系统 | 服务端 | 库存扣减与回滚、库存流水记录 |

> **注**：本版本不区分管理员角色，商品与用户数据由 `seed.sql` 预置。

## 4. 非功能需求

| 编号 | 类别 | 需求描述 |
| --- | --- | --- |
| NFR-001 | 性能 | 单接口响应时间在本地环境下应 < 500ms（并发缺陷延迟除外） |
| NFR-002 | 并发 | 系统应支持不少于 20 个并发下单请求而不产生数据错误 |
| NFR-003 | 安全 | 用户密码不得明文返回；token 应对使用者不可猜测（随机 32 位十六进制） |
| NFR-004 | 安全 | 所有涉及资源归属的接口必须做水平越权校验 |
| NFR-005 | 数据一致性 | 商品库存 = 初始库存 + 所有库存流水变动之和 |
| NFR-006 | 兼容性 | 支持 Chrome / Edge / Firefox 最新版 |
| NFR-007 | 可维护性 | 数据库连接信息集中配置，支持环境变量覆盖 |

## 5. 数据字典

数据库名 `easybuy_mall`，字符集 `utf8mb4`，引擎 `InnoDB`。

| phone | VARCHAR(20) | NULL | 手机号 |

| 字段 | 类型 | 约束 | 说明 |

| user_id | INT | FK → users.id | 所属用户 |

### 5.4 carts（购物车表）

| 字段 | 类型 | 约束 | 说明 |

| user_id | INT | FK → users.id | 所属用户 |
| product_id | INT | FK → products.id | 商品 |
| quantity | INT | NOT NULL | 数量 |
| — | — | UNIQUE(user_id, product_id) | 同人同商品只有一行 |

### 5.5 orders（订单表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 订单 ID |
| user_id | INT | FK → users.id | 下单人 |
| amount | DECIMAL(10,2) | NOT NULL | **实付金额** = 商品小计 − 优惠金额 |
| total_amount | DECIMAL(10,2) | NOT NULL, DEFAULT 0.00 | 商品小计（各明细单价×数量之和） |
| discount_amount | DECIMAL(10,2) | NOT NULL, DEFAULT 0.00 | 优惠金额（用券减免的部分） |
| user_coupon_id | INT | NULL | 使用的用户券 ID（软引用，无外键） |
| status | VARCHAR(20) | DEFAULT 'PENDING' | 状态（PENDING / PAID / CANCELLED） |
| pay_type | VARCHAR(20) | NULL | 支付方式 |
| created_at | DATETIME | DEFAULT NOW() | 下单时间 |
| paid_at | DATETIME | NULL | 支付时间 |

### 5.6 order_items（订单项表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 明细 ID |
| order_id | INT | FK → orders.id | 所属订单 |
| product_id | INT | — | 商品 ID（下单快照） |
| product_name | VARCHAR(100) | NOT NULL | 商品名（下单快照） |
| price | DECIMAL(10,2) | NOT NULL | 成交单价（下单快照） |
| quantity | INT | NOT NULL | 数量 |

### 5.7 stock_logs（库存流水表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 流水 ID |
| product_id | INT | FK → products.id | 商品 |
| change_qty | INT | NOT NULL | 变动量（扣减为负，回滚为正） |
| reason | VARCHAR(30) | NOT NULL | 原因（INIT / ORDER_CREATE / ORDER_CANCEL） |
| order_id | INT | NULL | 关联订单 |
| created_at | DATETIME | DEFAULT NOW() | 时间 |

### 5.8 coupons（优惠券模板表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 券 ID |
| code | VARCHAR(32) | UNIQUE, NOT NULL | 券码 |
| name | VARCHAR(60) | NOT NULL | 券名称 |
| type | VARCHAR(20) | NOT NULL | 类型：`THRESHOLD` 满减 / `DISCOUNT` 折扣 / `FREE` 无门槛 |
| threshold | DECIMAL(10,2) | NOT NULL, DEFAULT 0.00 | 使用门槛（小计需满此金额） |
| value | DECIMAL(10,2) | NOT NULL | 券值：满减/无门槛 = 减免金额；**折扣 = 折扣率**（0.88 表示 88 折） |
| total_count | INT | NOT NULL, DEFAULT 0 | 发放总量（0 = 不限量） |
| claimed_count | INT | NOT NULL, DEFAULT 0 | 已领取数量 |
| per_user_limit | INT | NOT NULL, DEFAULT 1 | 每人限领张数 |
| valid_from / valid_to | DATETIME | NOT NULL | 生效 / 失效时间 |
| status | VARCHAR(20) | DEFAULT 'ACTIVE' | ACTIVE 可领 / DISABLED 停发 |

> `value` 字段是「一列两义」：满减券存**减免金额**，折扣券存**折扣率**。
> 这正是 BUG-007 的温床 —— 代码把折扣率直接当减免比例用了。

### 5.9 user_coupons（用户优惠券表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 用户券 ID |
| user_id | INT | FK → users.id | 持有用户 |
| coupon_id | INT | FK → coupons.id | 券模板 |
| status | VARCHAR(20) | DEFAULT 'UNUSED' | 状态：UNUSED / USED / EXPIRED |
| order_id | INT | NULL | 使用该券的订单（**故意不加外键**，避免与 orders 循环依赖） |
| claimed_at | DATETIME | DEFAULT NOW() | 领取时间 |
| used_at | DATETIME | NULL | 使用时间 |

> **数据一致性反向校验公式**：
> `products.stock == SUM(stock_logs.change_qty WHERE product_id = products.id)`
> 任何一次下单 / 取消，两侧都必须同步变化，否则说明出现了不一致 ——
> 这是发现 BUG-002、BUG-003 的关键校验手段。

## 7. 状态机

```
                    ┌─────────────┐
   下单成功  ──────▶ │  PENDING    │  待支付
                    │  待支付      │
                    └──┬───────┬──┘
             支付成功   │       │  取消
                       ▼       ▼
              ┌──────────┐  ┌──────────────┐
              │  PAID    │  │  CANCELLED   │
              │  已支付   │  │   已取消      │
              └──────────┘  └──────────────┘
                   ▲                ▲
                   └────────────────┘
                  这两条路径在本版本被错误放行 ── BUG-001
```

| 起始状态 | 事件 | 应有结果 | 本版本实际结果 |
| --- | --- | --- | --- |
| PENDING | 支付 | → PAID | ✅ → PAID |
| PENDING | 取消 | → CANCELLED，回滚库存 1 次 | ✅ 正确 |
| PAID | 支付 | ❌ 拒绝（400） | ✅ 拒绝（但代码未校验，见 BUG-001 说明） |
| PAID | 取消 | ❌ 拒绝（400） | ❌ 放行 → CANCELLED，**BUG-001 / BUG-002** |
| CANCELLED | 支付 | ❌ 拒绝（400） | ❌ 放行 → PAID，**BUG-001** |
| CANCELLED | 取消 | ❌ 拒绝（400） | ❌ 放行，库存 **重复回滚**，**BUG-002** |
