用例编号与代码里的 docstring 一一对应，可用 `pytest -k "TC-USER"` 之类按模块筛选。

## 五、缺陷复现模块（BUG，5 条 · 全部稳定复现）

这 5 条是**专项攻击用例**，期望结果写的是「正确系统应有的行为」，
当前被测系统不满足，因此标记为 `xfail`（期望失败）—— 它们「失败」才说明缺陷被真实抓到。

| 编号 | 对应用例 | 类型 | 期望（正确行为） | 实际 |
|---|---|---|---|---|
| BUG-001 | `test_bug001_cancelled_order_should_not_be_payable` | 状态机 | 支付已取消订单 → 400 | **200，状态变 PAID** |
| BUG-002 | `test_bug002_cancel_twice_should_not_restore_stock_twice` | 幂等性 | 二次取消 → 拒绝，库存仍 50 | **200，库存虚增至 52** |
| BUG-003 | `test_bug003_concurrent_order_should_not_oversell` | 并发 | 库存 3，30 并发 → 最多 3 单成功 | **30 单全成功，库存 −27** |
| BUG-004 | `test_bug004_cannot_read_others_order` | 越权 | B 读 A 的订单 → 403/404 | **200，返回完整明细** |
| BUG-004 | `test_bug004_cannot_cancel_others_order` | 越权 | B 取消 A 的订单 → 403/404 | **200，A 的订单被取消** |

详见 [缺陷报告.md](缺陷报告.md)。

## 用例设计说明

| 方法 | 用在哪 |
|---|---|
| 等价类划分 | 手机号格式（合法/非法）、登录凭据（对/错/不存在）、不存在的资源 ID |
| 边界值分析 | 密码 0/1/5/6 位、库存 3 下单 3 vs 4、分页 size=1 与超范围、空购物车 |
| 状态迁移测试 | 订单 PENDING→PAID、PENDING→CANCELLED，以及非法迁移 |
| 错误推测法 | 未带 token、伪造 token、重复取消、重复提交、他人资源 |
| 场景法 | 登录 → 加购 → 下单 → 支付 → 查询 完整链路 |

## 未覆盖（后续可扩展）

- 库存扣减为 0 后再次下单的连续场景（多用户串行）
- 订单金额的浮点精度（如 99.99 × 3）—— 已有疑点，未列为正式缺陷
- 商品下架后再结算
- 性能压测（并发上限、响应时间 P95）
