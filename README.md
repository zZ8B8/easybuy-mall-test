# 易淘商城 · 接口自动化测试实践

一个 **B2C 电商后端**的接口测试实践项目：被测系统（SUT）+ pytest 自动化测试套件 + 完整测试文档。

项目目标是完整跑通一遍测试工作流 —— **需求分析 → 用例设计 → 脚本编写 → 执行 → 缺陷定位 → 回归验证 → 测试报告**，
并且每个缺陷都真实存在于代码里、可复现、可定位到具体行。

> 说明：这是一个**个人测试实践项目**。被测系统由本人按典型电商业务逻辑实现，
> 缺陷是刻意保留的真实编码疏漏（不做任何标记），供测试用例去发现。

## 2. 快速运行

被测系统**零第三方依赖**，Python 3.8+ 直接跑：

```bash
# 启动服务（默认 127.0.0.1:5001）
python sut/server.py

# 另开一个终端做冒烟检查
python tools/smoke_check.py
```

跑自动化测试需要 pytest：

```bash
pip install -r requirements.txt

# 全量测试
pytest

# 只看缺陷复现
pytest tests/bugs -v

# 看每个缺陷的实际观测值
python tools/collect_evidence.py
```

Windows 用户可直接双击 `一键运行测试.bat` ——
脚本会**自己探测**机器上可用的 Python 解释器（不依赖 PATH 里的 `python`，
因为 Windows 上它常常是微软商店的占位符），缺 pytest 会自动安装，然后直接跑测试。

## 4. 发现并定位的缺陷

| 编号 | 标题 | 级别 | 类型 | 根因 |
|---|---|---|---|---|
| BUG-001 | 已取消订单仍可支付成功 | 高 | 状态机 | `pay_order` 未校验订单当前状态 |
| BUG-002 | 重复取消订单导致库存虚增 | 高 | 幂等性 | `cancel_order` 缺幂等校验，库存被重复回滚 |
| BUG-003 | 并发下单超卖 | 严重 | 并发 | `create_order` 中「校验库存」与「扣减库存」非原子，无锁保护 |
| BUG-004 | 可查看并取消他人订单 | 严重 | 越权 | 订单详情 / 取消接口未做归属校验 |

四条缺陷对应的测试用例**故意写成「期望失败」**（`pytest.mark.xfail`），
因为当前被测系统确实存在这些问题。测试全绿 = 功能符合预期 + 缺陷稳定暴露。

细节见 [docs/缺陷报告.md](docs/缺陷报告.md)。

## 6. 用到的测试方法

- **等价类划分**：手机号 / 密码 / 分页参数的合法与非法输入
- **边界值分析**：密码 5 位 / 6 位、库存恰好相等、分页超出范围、每页 1 条
- **状态迁移测试**：订单 PENDING → PAID / CANCELLED，以及非法迁移（已取消再支付、已支付再取消）
- **数据一致性校验**：下单 / 取消前后直接读内存比对库存与库存流水
- **并发测试**：`threading.Barrier` 让 30 个线程对齐后同时发起下单请求
- **幂等性测试**：重复提交同一操作，断言副作用不叠加
- **越权测试（水平权限）**：换一个用户身份访问他人资源，断言被拒绝

## 7. 技术要点

- 被测系统只用 Python 标准库，**clone 下来不用装任何东西就能跑**，避免"环境跑不起来"成为障碍
- 测试会话共用一个服务实例（`scope="session"`），每个用例前自动重置内存数据，用例之间零污染
- 断言直接比对**内存里的真实库存**，而不是只看接口返回值 —— 接口返回成功不代表数据正确
- 并发用例把「加购」串行执行、只让「下单」并发，把干扰因素排除在并发窗口之外

## 8. 已知局限

- 内存存储，无持久化；服务重启后数据重置（不影响测试结论）
- `service.DB_ROUND_TRIP` 是对数据库往返延迟的**模拟**，用于让并发缺陷可稳定复现
  （真实系统中这段延迟来自 SQL 执行与网络 IO），数值可调
- 未覆盖性能测试、安全测试（SQL 注入 / 越权等），后续可扩展
